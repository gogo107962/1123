2. 한 일

앱 흐름 (팀 화면 파일 청년비서_앱.html 기준)

  • 내 정보 입력 → 맞는 정책 추천 → 챗봇으로 찾기 → 상세 조건 대조 → 신청 계획 → 신청 전 점검 → 승인 뒤 저장까지 이어집니다. 화면은 static/mobile.* (React 없이 옮김).
  • 챗봇은 로컬 Ollama(qwen3:4b)가 검색어만 고르고, 문장은 서버가 정해진 틀로 만듭니다. 모델이 꺼져도 낱말 일치로 동작합니다. 실제 모델 평가 40문항 중 40문항 형식·검색어 통과(최신 코드로 다시 실행, 응답 중앙값 2.1초).
  • 질문 선택기: 찾은 정책을 가장 많이 가르는 항목 하나(지역·나이·취업·받는 지원·학력·거주 기간)를 묻고, 가를 정책이 없으면 묻지 않습니다(MVP 구조 문서의 도구).
  • 거주 기간: 내 정보에 “지금 사는 곳에 산 기간”을 넣으면 “1년 이상 거주” 같은 조건과 비교합니다(프로토타입의 “전입한 달”).

데이터 구조화

  • 수집 필드 41개를 모두 구조화: 나이, 신청기간, 지역, 소득, 취업·학력·전공·결혼, 참여 제한, 제출서류, 신청 방법, 지원 규모·선착순, 사업기간, 심사 방식, 금액 표현, 대상 집단.
  • 시군구 이름 261개를 행정표준코드관리시스템(code.go.kr)에서 코드마다 확인. 2026-07-01 폐지된 인천 중구·동구·서구 표시.
  • 명세에 뜻이 없는 값은 온통청년 누리집의 표시 코드에서 확인: 연령·규모 표기 Y는 “제한없음”, 연소득 단위는 만원, 선착순 표기 Y는 “선착순”. 근거는 data/api_field_notes.json.
  • 빈칸, 0, “-”, “해당없음”을 “제한 없음”이나 “서류 불필요”로 바꾸지 않습니다.

판별 엔진

  • 두 층입니다. 걸러보기(screening.py)는 API 값 비교로 맞아요/확인 필요/달라요를 내고, 규칙 엔진(engine.py)은 사람이 승인한 정책에만 4상태 판정을 냅니다.
  • 신청기간이 300일 이상이면 사업기간으로 보고 “접수 중”이라 하지 않습니다. 선착순 표기도 “확인 필요”입니다.
  • 공식 페이지에서 확인한 문장을 판정에 씁니다. 공식 기간이 분명하고 오늘이 그 안이면 “맞아요” 유지, 지났으면 “확인 필요”.
  • 중복 수혜 제한은 A→B 방향만 적용하고 뒤집지 않습니다.
  • 사람 검수 화면 /review: 초안을 열어 출처 문장을 확인하고 검수자 이름을 적어야 승인됩니다. 서버나 AI가 스스로 승인하는 경로는 없습니다.

검증

  • 자동 테스트 352개 통과(저장소를 빈 폴더에 새로 받은 환경에서도 통과). 실제 4,020건 × 가상 프로필 12개 = 48,240번 판정에서 규칙 위반 0건.
  • 실제 브라우저 흐름 테스트 2종 통과(로컬 Ollama 응답 약 10초 포함).

3. 팀이 알아야 할 발견

중요 API는 접수 중인데 공식 페이지에서는 이미 끝난 정책 13건

광주 청년창업특례보증, 평택 취업성공·우수초기창업자·크라우드 펀딩, 울산 AX 리더십·웹툰캠퍼스·U-미디어팩토리, 광산구 임대료, 대구 게임아카데미, 동구 청년 웰컴 박스, 천안 버스 운전자, 게임사 현장교육, 부산 중개보수·이사비 지원. API의 신청기간이 사업기간이거나 회차가 일찍 끝난 경우입니다. 시연에 쓸 정책은 공식 페이지에서 접수 여부를 꼭 확인해야 합니다.

확인 팀 대조 결과와 맞춰 본 것

  • 서울청년문화패스 나이: 공식 페이지에 “21세~24세(2002~2005년생)”. API는 21~23. 팀 기록과 일치.
  • 고립·은둔 청년 나이 39 → 34: 공식 페이지에서 19~39세로 나와 재현하지 못했습니다. 어느 공고를 보셨는지 알려 주세요.
  • 전세보증금반환보증 소득: API는 “무관” 또는 5,000~7,500으로 적혀 있지만 실제는 청년 5천만원·신혼부부 7,500만원 이하. 이제 “확인 필요”로 나옵니다.

확인 API 값의 함정

  • 연소득 최소 칸이 하한이 아니라 다른 대상의 상한으로 쓰인 정책이 있습니다(8건). 두 값이 있으면 비교하지 않습니다.
  • 나이 범위와 “제한없음(Y)”이 함께 적힌 정책이 774건입니다. 범위 밖이어도 “달라요”라 하지 않고 “확인 필요”로 둡니다.
  • 코드표(API코드정보.xlsx)의 분류 이름은 옛 목록입니다. 데이터에 옛 이름 774건과 새 이름이 섞여 있어 새 이름으로 맞췄습니다.

4. 팀에 부탁할 것

  • 팀 폴더 파일 전달: final_candidates.json(최종 후보 26건), region_codes.json, 원문_대조_결과.md가 제 PC에 없습니다. 받으면 원문 대조 결과를 바로 반영하겠습니다.
  • 검수·승인 담당 정하기: 실제 자격 판정은 /review에서 초안을 승인해야 나옵니다. 시연용 정책 2~4개만 승인해도 4상태 판정을 보여 줄 수 있습니다.
  • 재수집 여부: 코드표의 4개 코드(정책특화 요건, 제공 방법, 승인 상태, 제공기관 그룹)는 수집 때 저장하지 않아 값이 없습니다. 다시 수집하면 채워집니다.
  • 문서끼리 다른 부분 결정: 상태 문구(신청 검토 가능/조건 불충족 ↔ 맞아요/확인 필요/달라요), 인프라(Vercel·Gemini ↔ 로컬 Ollama만), 다음 모집 예상 표시(기획 ↔ 추정 금지 원칙).

5. 아직 없는 것

  • 사람 검수로 승인된 실제 정책 (0건)
  • 건강보험료 기준, 부모·부부 합산 소득, 재산·자산 기준 비교 — 정책마다 표와 산정 방식이 달라 “확인 필요”로 남깁니다
  • 지원 금액 합산 — 대출과 지원금을 구분할 값이 없습니다
  • 다음 모집 예상 시기, 매일 최신화 — 추정 금지·재수집 금지 원칙과 충돌
  • 인용 문장이 원문에 실제 있는지 자동 대조, 사람이 정한 정답셋과 일치율
  • 로그인, 공개 배포

6. 실행과 파일

  • 앱 실행: .\.venv\Scripts\python.exe -X utf8 start.py → http://127.0.0.1:8000

7. 한계

  • 공식 페이지 확인은 조회 도구가 연 페이지의 문장을 옮긴 것이고, 첨부파일(hwp·pdf)은 대부분 열지 못했습니다. 모두 사람 검수 전입니다.
  • 연령·규모 표기의 뜻과 금액 단위는 공식 명세가 아니라 누리집 표시 코드에서 읽은 것입니다.
  • 참여 제한과 대상 집단은 낱말 일치로 분류할 뿐 문장의 뜻을 판정하지 않습니다.
  • 가상 프로필만 씁니다. 실제 개인정보는 받지 않고, 프로필은 브라우저에만 저장됩니다.
