# 다음 작업: 중단 지점부터 검증하고 완성하기

기능을 새로 늘리기 전에 마지막 코드표/앱 UI 변경의 안정성을 확보한다. 이전 코드가 검증됐다는 사실로 새 변경을 통과 처리하지 않는다.

## P0-1. 현재 변경 확정

1. 최신 인계서·실제 파일·DB를 대조한다. Git이 미추적 상태이므로 `git diff`가 비어 있다고 변경이 없다고 결론내리지 않는다. 패키지 manifest/hash를 기준으로 파일을 비교한다.
2. 전체 pytest를 실행해 실제 통과 개수/경고/시간을 기록한다. 현재 근거는145전체+13desk부분이며147전체성공이아니다.
3. 새 코드 기능에 의미 있는 회귀를 추가한다.

## P0-3. 전국 데이터의 안전한 해석

전국탐색은모두유지한다. 지역이나20건제한으로되돌리지않는다. 동시에검수깊이와데이터폭을구분한다.

1. zipCd의공식코드표/버전/변경근거확보. 파일에없는12계열을추측하지않음. 제공기관소재지와지원대상지역을구별.
2. 금액단위·개인/가구·산정연도·소득항목·공제·기준중위소득의근거확보. 이중하나라도필요한데없으면확인필요.
3. 나이min/max의기준일과Y/N의실제의미확인. 숫자0/빈값을무제한으로치환하지않음.
4. 전국가상프로필의저장방식설계. 기존lab regionenum을그대로전국대표라고하지않음. 실제개인정보입력불필요.
5. 판정카드에원문근거/검수범위/불확실성을표시. 기존4종API기간배지는개인자격4종판정을대체하지않음.

현재코드표는이작업의일부만해결했다. API허용값을안다고모든예외/중복수혜/서류발급기한을알게되는것은아니다.

## P0-4. 심사에 의미 있는 한 흐름 통합

가상프로필→전체정책탐색→선택정책의근거조회→필요한질문→검수된규칙의조건/방향성충돌→서류준비→사용자승인→DB저장/복원으로연결한다.

- 질문은누락사실과해당정책의실제분기에연결하고대답에따라결과가바뀌어야한다. 지금questions는일반공고확인질문이다.
- 충돌플래너는검수된A→B방향과지원대상기간에근거한다. 모르는조합은‘충돌없음’이아닌‘추가확인’.
- 순서는실제선행조건이있는경우에만추천. 지연/마감/중복의근거없는최적화주장금지.
- 서류세칸은‘원문에서확인한요건 / 추가확인필요 / 사용자가준비표시’처럼의미를정하고,보유표시를유효서류검증으로오해하지않게한다.
- 실제정책의전체조건검수전에는approved플래그를올리지않는다. 사람검수이름/일자를자동으로지어내지않는다.
- LLM을꺼도검색/규칙/미리보기/승인/저장은가능해야한다. AI비가용상태를정확히표시하고고정문구를실제AI응답이라고부르지않는다.

## P1. 평가·배포·제출 준비

20개정답질문은정책수20개제한이아니다. 실제근거·기준일·예외·예상판정·추가질문·서류·출처로골든셋을구성한다. 범용AI대조는동일입력/시점/출처/채점기준을기록하고실제실험값만발표한다.
운영자검수비용, 정책갱신시기존작업무효화, LLM지연/실패/로컬하드웨어제약, 데이터수집품질을실측한다. 무료는소프트웨어/API과금구성의뜻이지전력/하드웨어비용이0이라는뜻이아니다.
배포는기존로컬전용검수API, 인증없는관리기능, workspace토큰, 로컬Ollama접근을검토한구체적안을먼저준비한다. 사용자최종의도/환경에맞게진행하고공개URL없이배포완료라고하지않는다.
