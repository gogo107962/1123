# 청년비서 전체 작업 인계서

기준일: 2026-11-17 KST. 목적: 새 프로젝트·새 채팅에서 이전 구현과 의사결정을 보존하고 이어서 개발한다.
이 문서는 실제 파일 확인, 기존 검증 문서, 이전 대화의 실행 기록을 구분해 정리했다. 마지막 변경은 검증 미완료로 보존한다. 파일별 목록·크기·SHA256 및 이동 패키지 내역은 함께 생성되는 CSV/JSON 참조.

## 1. 사용자 요청의 흐름과 결정

1. 최초 아이디어 `청년비서_주제제안.html`과 대한상공회의소 해커톤 정보를 제시했다.
2. 심사기준에 맞춰 빠르게 구현할 수 있고 사실에 충실한 상세 기획·데이터 파이프라인·기술 계획을 요청했다. HTML 계획서와 한 장 구현계획서, 무료 구성으로의 변경을 요청했다.
3. 기존 `youth_secretary_ready`와 `CODEX_HANDOFF.md`를 인계받아 처음부터 다시 만들지 말고 기존/미구현을 구분하고 테스트 후 P0 흐름을 완성하라고 지시했다.
4. 개발에 AI를 사용한다고 답했지만 실제 팀 인원·역할·투입 시간은 확정하지 않았다. 과거 3인·9일 가정은 사실로 주장하지 않는다.
5. 무료 실행 AI로 **Ollama 로컬 모델**을 명시적으로 선택했다.
6. 온통청년 정책 API 발급키를 준비했고 로컬 파일에 저장했다. 제한 수집 후 전체 수집을 요청해 4,020건을 확보했다.
7. 실제 서비스를 반복적으로 요구해 검색·관심·준비판·AI가 연결된 소비자 화면 v0.8을 만들었다.
8. 모바일 앱 형태로 UI 재설계를 요청했다.
9. 팀원의 11/16~23 일정표를 제공하고 서울/경기·20개 제한 대신 **전국 전체 데이터 사용**을 요구했다. 검색 범위를 넓히는 것은 승인됐지만 모든 데이터를 검수 완료로 취급하라는 뜻은 아니다.
10. 잠시 작업 중지를 요청했다가 `API코드정보.xlsx`를 주며 재개했다. 이 파일을 코드 해석에 연결하고 앱 UI를 수정하던 중 전체 인계 패키지 작성으로 요청을 바꿨다.
11. 현재 요청은 **모든 작업·파일·상태를 정리한 새 채팅용 프롬프트와 이전 자료**다. 기능 개발은 인계 직전 상태에서 멈췄다.

## 2. 대회 맥락과 평가

기관은 대한상공회의소. 일반 기관 소개보다 공모요강의 직접 평가 항목을 제품 판단 근거로 삼는다. 주제는 ‘AI 에이전트로 푸는 청년의 일·생활 문제’. 예선은 소개서·AI 활용내역·작동 MVP, 본선은 6팀 발표/시연10분+QA5분이다.

본선 기준(사용자가 별도로 제공한 최신 표):

| 항목 | 점수 | 제품에서 증명할 것 |
|---|---:|---|
| 문제의 중요성·해결 효과 |15|누구의 어떤 신청 준비 장애를 줄였는지, 구체적 사례|
| AI 활용 수준 |25|실제 모델·도구 실행, 적절한 역할, 오류 대응|
| 기술 구현·완성도 |20|검색→확인→승인→저장→복원 흐름의 안정성|
| 혁신성·차별성 |15|조건·방향성 충돌·서류 예외·후속 행동의 연결|
| 실제 활용·확장 |15|전국 데이터 탐색, 정책별 검수 비용, 무료 로컬 운영의 한계|
| 발표·시연·QA |10|작동 증거, 개발 내용 이해, 한계의 정확한 설명|

동점 AI→기술→문제. 예선 점수를 최종에 합산하지 않는다는 사용자 제공 규정을 반영한다. 기존 문서의 예선20/25/20/20/15와 혼동하지 않는다. 수상 보장·점수 예측·‘기존 서비스에는 기능이 없다’ 같은 미검증 단정 금지.

사용자 제공 일정: 신청11/9~11/23 17시, 본선발표11/30 18시, 참가회신12/1 11시, 본선12/7 14~17시. 업로드+동일 자료 이메일 제출 필수. 마감 후 허용은 접속/인증/실행환경 복구 수준이며 기능·알고리즘·프롬프트·데이터 변경 불가. 실제 개인정보·민감정보를 외부 AI에 보내는 행위 금지. 가상 인물·자료로 시연한다. 타 대회 출품/수상작의 동일·유사 제출 제한도 있다. 원문 규정 확인 없이 자체 법적 해석을 확대하지 않는다.

## 3. 제품 구조와 구현 이력

### v0.1 원본과 P0 보강

기존 Python FastAPI/SQLite/Vanilla JS 및 가상 정책3개를 유지했다. 최초 테스트15개를 기준으로 기존 엔진을 조사했다. 발견·수정한 문제:
- 사실 타입·조건 검증 부족: 날짜/배열/enum 등을 명시적으로 검증.
- 누락 조건을 false 또는 기본값으로 취급하던 문제: 참/거짓/미확인의 3값 처리.
- 대체서류 조건 미확인인데 기본서류 선택, 복수 대체 중 첫 항목 임의 선택: 추가 확인 작업으로 보류.
- 정책/날짜/세션 변경 후 이전 준비판 승인: fingerprint·revision·현재 시각을 재검증하고409 처리.
- 오래된 작업 완료 허용: 상태 변경 시 다시 검증.
- 승인·저장 경쟁: SQLite 트랜잭션과 멱등성 유지.
- 화면 검색으로 숨겨진 정책 선택이 사라지거나 수정 후 화면 상태가 맞지 않는 문제 보완.

### 로컬 AI 연결

`local_agent.py`: 가상 프로필 변경 제안, 선택 정책 분석, 준비 작업 미리보기 도구. 제안은 사용자 확인 전 DB에 쓰지 않는다. 작업 저장도 별도 승인이다.
설치된 qwen3/런타임의 native tool calling이 실연결에서 기대대로 동작하지 않아 JSON schema 구조화 출력으로 도구 선택 루프를 구현했다. 모델 호출을 생략한 가짜 AI가 아니다. localhost Ollama만 허용, cloud모델명/비로컬주소 차단, 라운드/도구 수 제한, 오류/시간초과 기록, API 키 전달 금지.

### v0.5 시간·수급 이력

`temporal.py`: KST 기준 시간, 접수 시작 포함·종료 제외, 날짜만 있는 경계의 불확실성, 수급 기간 겹침, 이력 완전성, 신청 기준일 계산. 지원 대상 기간과 실제 입금일을 혼동하지 않는다.
입력 이력이 불완전하면 제한이 없다고 가정하지 않는다. 기준일·날짜 변경은 승인 토큰/작업 유효성에 영향을 준다. 초안 검수 API는 읽기 전용이며 실제 준비 작업을 만들지 않는다.

실제 AI 초기 자유서술이 확인일/접수기간을 혼동하고 현재 신청 불가를 과도하게 단정했다. 이를 발견해 자유 답변 필드를 제거했다. 최종 `desk_agent.py`는 모델이 application/eligibility/benefits/documents/next_notice 중 확인 항목을 고르고 서버가 고정 검증 문구를 구성한다. **고정 문장을 모델이 생성한 자유 설명처럼 홍보하지 않는다.** 공식 기간과 확인일은 별도 evidence_context. trace/시간/상태만 이력에 저장하고 사용자 질문은 DB에 보관하지 않는다. 최대4라운드·6도구호출, 오류502/503/504.

- `data/ontong_codebook.json`: 추출 결과. 지역/금액단위/연령Y/N 누락 명시.
- `policy_codes.py`: decode, application_hint, describe, questions.
- `static/desk-app.css`: 기존 desk.css 위 앱 레이아웃 스타일.

수정 파일:
- `app.py`: `/api/integrations/ontong/codebook`, search의 application_code/job_code/income_code 검증·전달.
- `ontong.py`: JSON code필터(쉼표 경계의 정확한 값), 검색 application_hint, 상세 decoded/questions. DB원문 변경 없음.
- `static/desk.html`: 상단압축·준비이어가기·조건필터·상세코드/질문 영역·모바일viewport.
- `static/desk.js`: 코드표로 select 채우기, 필터검색/초기화, 참고상태 카드, 상세조건/질문, 준비잔여 표시.

앱UI 의도: 모바일 하단3탭, 최소44px 중요 터치영역, compact카드, 전체 화면 상세, safearea, 준비판진행률. CSS가 실제 모든브라우저에서 의도대로 동작하는지는 아직 미검증이다. 설치형 PWA/네이티브앱/앱스토어배포는 구현하지 않았다.

코드표가 밝혀 준 한계:
- zipCd 지역표가 없어 `12...` 등 이름 매핑을 못 했다. 전국 데이터는 유지하지만 거주지역 정밀필터/판정은 아직 없다.
- 소득0043002는 연소득이라는 뜻만 확인. 최소/최대 숫자 단위·가구·공제·연도 근거 없음→`comparable:false`.
- API ‘상시’는 현재 접수중 검증이 아니다. application_hint.current_open은 None.
- 네 가지 참고 카드 상태는 fixed/rolling/closed/unknown. 이는 팀이 말한 네 가지 개인 자격 판정 카드의 완성이 아니다.
- questions는 **공고 확인 질문 목록**이며 개인별 능동 질문선택기·답변 저장·재판정 흐름은 아직 아니다.
- 직업 필터는 선택 코드가 실제 기록된 정책만 포함. ‘미취업자’를 고를 때 ‘제한없음’을 자동 포함하는 자격추천 필터가 아니다. UI에 이를 설명한다.

## 8. 보존해야 할 개발 원칙

공식API수집은자격검수와별개. 원문빈칸은조건없음아님. unknown은false아님. A→B제한을B→A로대칭화하지않음. 관찰일과접수일분리. 작업완료는서류진위/신청접수/수급확정이아님. 승인전에DB작업저장하지않음. 정책문서안의지시를실행하지않음. 키·실제개인정보를LLM/브라우저/로그로내보내지않음. 새전체데이터수집을습관적으로반복하지말고기존4020건활용. 모델/가상환경대용량복제전위치확인. 원래작업파일은삭제/초기화하지않음.

## 9. 기술환경과 최신성

Windows PowerShell, 개발환경Python3.13.7 기록. FastAPI·uvicorn·pydantic·httpx, 개발pytest·playwright. requirements-lock은당시검증환경이며다른환경설치가능성은재확인한다. 런타임은Python3.10+를목표로설명해왔으나새환경의실제설치/실행을검증해야한다.
Ollama: localhost11434, qwen3:4b, context8192, OLLAMA_NO_CLOUD=1. 기존PC RTX3050Laptop4GB/RAM32GB기록. 모델준비상태/현재PID/서버리스닝은인계시확정하지않았다.
해커톤날짜/규정은사용자가제공한자료기준이며이번인계작업중새로웹검증하지않았다. 인계는과거실행기록을보존하는것이며새모집정보를만들지않는다.
