# 기존 프로젝트 분석 및 P0 실행계획

기준: 2026-11-15, 제공된 CODEX_HANDOFF.md와 실제 코드. 다운로드 폴더의 동일 이름 `(3).zip`을 사용했으며 요청 경로의 `(2).zip`은 없었다. 기존 FastAPI / SQLite / Vanilla JS와 6개 화면 섹션을 유지한다.

2026-11-16 결과: v0.7에서 전체 테스트 134개, 온통청년 4,020건 검색·원문 대조·조기 마감 검토의 브라우저 흐름이 통과했다. 실제 Ollama 정보 제안·세 도구 호출·승인·DB 저장도 재검증했다. 공식 정책의 전체 조건 검수와 공개 배포는 남아 있다. 상세 증거 및 한계는 [VALIDATION.md](VALIDATION.md)를 기준으로 한다.

## 착수 시 구현 상태

| 영역 | 이미 구현 | 부족하거나 결함이 있는 부분 |
|---|---|---|
| 데이터 입력 | JSON 검증, 정규화 저장, 승인 버전 불변, 초안 제외 | 원문 기반 실정책 없음, 조건 타입 검증 약함, 검수 대기 표시 없음 |
| 판별 | 3값 논리, 방향성 제외, 모집기간 | 빈 문자열 누락, 기준일 복잡한 규정의 수동 확인 장치 부족 |
| 서류 | 기본/대체서류, 조건별 병합, 보유 표시 | 대체 조건 미확인인데 기본 서류 확정, 복수 대체 조건 충족 시 첫 항목 임의 선택 |
| 저장 | 명시적 승인, 중복 방지, revision, 상태 변경 | 승인 대상 스냅샷 검증 없음, 정책 변경 후 stale 감지 없음, stale 작업 완료 허용 |
| AI | OpenAI 도구 호출 루프와 일부 기록 | 무료 로컬 연결 없음, 오류 경로 기록 누락, 실제 LLM 검증 없음 |
| 화면 | 정책 선택→분석→서류→준비판→AI | 검색 시 숨겨진 선택 해제, 미확인 값을 기본값으로 대체, 조건 수정 후 작업 상태 갱신 누락 |

## 작업 단위와 완료 조건

1. **P0 환경/기준 테스트**: 프로젝트 .venv 설치, 원본 테스트 15개 실행. 결과는 VALIDATION.md에 실제 실행 결과로 기록. 운영/개발 의존성 분리 및 재현용 잠금 파일.
2. **P0 판별/정책 입력**: 조건 타입 검증, 미확인 서류 보류, 다중 대체 후보 검수, 수동 검토 항목, 원문·검수 상태 노출. 실정책 2개는 원문이 있는 초안만 추가하고 승인하지 않음.
3. **P0 승인/DB 일관성**: 미리보기 토큰에 세션 revision·정책 내용·날짜를 결합. 승인 시 재계산/트랜잭션 검증. 오래된 작업 상태 변경 거부. 기존 DB는 추가 컬럼 마이그레이션.
4. **P0 무료 AI**: Ollama /api/chat 도구 호출, 제한된 라운드/도구 수, 로컬 주소만 허용, 실패·시간초과 기록, 읽기 가능한 실행 이력. 모델의 사실 추출은 제안 후 사용자 확인, 작업 저장 도구는 제공하지 않음.
5. **P0 통합 검증/인수인계**: 3개 페르소나 및 정책 입력→판별→서류→AI 도구→승인→SQLite 저장 회귀 테스트. 실제 서버 health/docs 확인, JS 구문 검증, 실행 설명 업데이트.

## 범위 및 남는 의존성

- 무료: 로컬 Python/SQLite/Ollama. 기존 PC의 메모리·전력·모델 다운로드 용량은 별도 자원이며 무료 API 호출을 흉내 내지 않는다.
- 실제 정책 검수는 담당자가 공식 공고의 모든 예외·기준일·증빙을 대조해야 한다. 날짜 이력을 현재 수급 코드 배열로 대체하지 않는다. 미표현 항목은 manual_checks로 보류한다.
- 공개 배포, 인증, 자동 신청, 실제 증빙 업로드, 복잡한 소득 계산은 이번 로컬 완성 범위 밖이다. 온통청년은 v0.6에서 사용자가 명시적으로 실행하는 제한된 API 수집을 추가했다.
- 모의 모델 응답으로 통과한 테스트는 실제 LLM 성공으로 표시하지 않는다. 모델 설치/실행 가능 여부와 실제 호출 증거를 별도 기록한다.
- 본선 평가: 15/25/20/15/15/10점. 인계서의 20/25/20/20/15는 예선 항목이므로 혼동하지 않는다. 점수 예상이나 수상을 보장하지 않는다.

## 추가 완료 (v0.5)

수급 기간과 신청 기준일 비교, 한국시간 접수 시각, 마감 경계의 승인 토큰 무효화, 수급 이력 입력 화면, 공식 초안 읽기 전용 검수 시뮬레이션을 구현했다. 전체 실제 정책 검수·공개 배포는 여전히 별도 작업이다.

## 추가 완료 (v0.6 · 2026-11-16)

사용자가 온통청년 정책 API 발급키를 준비함에 따라 기존 SQLite와 FastAPI에 수집 경로를 추가했다. `ontong.py`가 공식 API의 페이지 응답을 검증하고, 별도 후보·변경 스냅샷·수집 이력 테이블에 원자적으로 반영한다. 화면 02에서 정책명 검색, 원문 검토, 검토용 JSON 다운로드를 제공한다. 정책번호·내용 해시로 중복 저장을 방지하며, API 값이 기존 검수 정책이나 준비 작업을 덮어쓰지 않는다.

다음 우선순위는 수집한 정책 중 시연 대상 1~2건의 공식 공고·첨부 문서를 대조하여 규칙/서류 초안을 작성하고, 정답 사례와 사람 검수로 승인 조건을 충족하는 것이다. API 연동 여부는 해결했지만, 공식 정책의 전체 자격 검증은 해결된 것으로 간주하지 않는다. 기존 Ollama 도구 실행과 사용자 승인 구조는 유지한다.

## 전체 수집 다음 단계 (v0.7)

4,020건 전체 DB를 화면에서 검색·필터·페이지 이동할 수 있게 했다. 공식 출처 3건을 대조하여 API 기간 불일치, 접수 시각, 조기 마감을 기록하고 규칙 초안으로 이동시킨다. 성북구 응시료의 부분 규칙·서류 초안과 조기 마감 처리, 조건부 서류 회귀 사례를 추가했다. 자동으로 승인 상태를 올리지 않았다.

다음 P0는 시연 대상의 미표현 자격·중복 조건과 서류 예외를 공식 공고·FAQ로 채우는 것이다. 현재 확인한 세 공고는 종료 상태이므로, 이를 모집 중이라고 연출하지 않고 과거 시각의 검토 사례와 현재 마감 대응을 구분한다. 사용 가능한 모집 중 공고를 확보할 경우 별도 버전으로 입력하고 동일 검수 절차를 거친다. 그 다음 사용자 시연·발표 자료·심사 접근 환경을 준비한다.

## 서비스 구성 (v0.8 · 2026-11-17)

기존 6단계 화면을 /lab에 보존하고 / 및 /desk/에 실제 사용 화면을 연결했다. 전체 정책 검색, 관심 저장, 정책 상세/원문 대조, 준비 작업 미리보기와 승인, 완료/재접속 복원, 선택 정책에 대한 로컬 AI 도구 조회를 구현했다. 기존 DB와 수집 데이터는 유지하며 준비 공간 관련 테이블 4개를 추가했다.

미검수 정책을 억지로 승인하지 않고 실제 사용자가 공식 조건을 확인하는 작업을 관리할 수 있게 했다. 이 작업 관리와 개인별 적격·서류 판별은 구분한다. 후자는 기존 검수 정책/규칙 엔진의 범위이며 실제 정책 전체 검수와 공개 운영 준비는 계속 남아 있다.
