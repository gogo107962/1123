# 청년비서 제출 자료 초안 (2026-11-18 작성, 팀 검토 전)

제출 문서를 쓸 때 가져다 쓸 재료다. 수치는 모두 [VALIDATION.md](../VALIDATION.md)에 실행 기록이 있는 것만 적었다. 팀이 고쳐 쓰고, 여기 없는 내용(팀 구성, 일정, 팀원 쪽 작업)은 팀이 채운다.

## 1. 한 줄 소개

청년비서는 내 상황을 한 번 알려 주면 맞는 청년 정책을 찾아 주고, 조건이 왜 맞거나 다른지 근거를 보여 주고, 함께 받기 어려운 정책과 준비할 서류까지 정리해 신청 직전까지 데려가는 앱이다.

## 2. 문제와 해결

| 청년이 겪는 일 | 청년비서가 하는 일 |
|---|---|
| 정책이 3,995건이라 무엇이 나에게 맞는지 모른다 | 나이·사는 곳(시군구)·취업 상태·소득·받고 있는 지원으로 걸러, 맞는 정책을 마감이 가까운 순으로 보여 준다 |
| 공고가 길고 조건이 흩어져 있다 | 조건마다 "맞아요 / 확인 필요 / 달라요"와 근거 문장을 보여 준다 |
| 하나를 받으면 다른 하나를 못 받는 경우가 있다 | 정책의 참여 제한 문장에서 내가 받는 지원이나 함께 고른 정책을 찾아 그 문장과 함께 경고한다 |
| 서류를 정책마다 따로 챙긴다 | 고른 정책들의 서류를 합쳐 공통·개별로 나누고 발급처를 알려 준다 |
| 포털 정보가 공고와 다르다 | 수집값을 그대로 믿지 않는다. 코드 칸과 조건 글이 어긋나면 단정하지 않고, 공식 페이지에서 확인한 문장을 따로 보여 준다. 자격은 확정하지 않고 공식 공고·신청 페이지로 넘긴다 |

## 3. AI 활용 내역 (초안)

- 사용 모델: 로컬 Ollama `qwen3:4b`. 외부·유료 AI를 쓰지 않는다. 실제 개인정보를 받지 않고 가상 정보로 체험한다.
- AI가 하는 일: 사용자의 말에서 무엇을 찾는지 이해해 검색어를 고른다(예: "자격증 시험 쳤는데" → 자격증·응시료). 정책 상세에서는 정책 자료와 준비 작업을 조회하는 도구를 실행하고 무엇부터 확인할지 고른다.
- 코드가 하는 일: 조건 비교, 건수, 순서, 서류 합치기, 화면에 나오는 문장. AI의 자유 서술은 화면에 쓰지 않는다. 처음 연결했을 때 AI가 확인일과 접수기간을 혼동하고 신청 불가를 단정하는 것을 확인했기 때문이다.
- AI 오류에 대한 장치:
  - 출력은 정해진 형식만 받고, 어긋나면 통째로 버린다.
  - AI가 고른 검색어를 코드가 다시 거른다(숫자, 뜻 없는 낱말, 사용자 정보 낱말 제거).
  - 나이·지역·취업 상태는 사용자의 말에 그 표현이 실제로 있을 때만 받는다. 실제 모델이 "27살"을 지역 코드 27(대구)로 고르거나 "대학생"을 미취업자로 고른 사례를 보고 넣은 장치다.
  - 받아들인 값도 자동으로 저장하지 않고 "내 정보에 반영" 버튼으로 사용자가 정한다.
  - AI가 꺼지거나 응답이 틀리면 정해 둔 낱말로 찾고, AI가 한 일이 아니라고 화면에 밝힌다.
- 실제 모델 평가: 정해 둔 질문 40개에서 형식 유효 40/40, 검색어 적절 40/40, 응답 중앙값 2.1초·최대 8.2초(2026-11-18 최신 코드로 다시 실행). 공격 문장 5개는 모두 형식 안에 머물렀다. 한 번 실행한 결과이고 문항은 직접 정한 것이라 일반적인 정확도를 뜻하지 않는다.
- 개발에 쓴 AI 도구: Claude Code(구현·검증), Codex(초기 수집·초안). 팀이 한 일과 구분해 적을 것.

## 4. 데이터와 신뢰성

- 온통청년 정책 API 3,995건(2026-11-19 재수집. 11-16 수집 때는 4,020건이었고 그 사이 12건이 생기고 37건이 사라졌다). 수집값은 공고와 다를 수 있다. 팀 대조에서 45건 중 32건이 한 항목 이상 달랐다.
- 그래서 세 단계로 나눈다.
  1. 수집값 비교: "API 기재값 기준"이라고 표시한다. 빈값·0·상시를 "제한 없음"으로 바꾸지 않는다.
  2. 공식 페이지 보완: 공식 페이지에 그대로 적힌 문장과 출처를 따로 저장해 보여 준다(정책 77개·199개 항목, 사람 검수 전). 이 확인에서 API는 접수 중으로 적었지만 공식 페이지에서는 회차가 이미 끝난 정책이 13건 나왔고, 이런 정책은 '맞아요'로 보여 주지 않는다.
  3. 공식 페이지로 넘기기: 판정은 신청 준비를 돕는 비교이고 자격을 확정하는 것은 기관이다. 조건 줄마다 근거 문장과 그 근거가 온통청년 정책 페이지의 어느 항목에서 나왔는지를 보여 주고, 정책 상세와 신청 전 점검에서 공식 공고·신청 페이지·온통청년 정책 페이지로 넘긴다(3,995건 모두 연결).
  - 사람이 출처 문장을 확인해 승인하는 검수 화면(`/review`)도 있지만 서비스에 꼭 필요한 단계는 아니다. 현재 승인된 실제 정책은 0건이고 초안 11건이 있다.
- 전체 데이터 점검: 코드표에 없는 코드 0건, 같은 정책 중복 등록 316건(묶어서 표시), 참여 제한 문장이 있는 정책 623건('해당 없음'만 적힌 132건은 따로 구분), 나이 상한이 99 이상으로 적힌 정책 84건(2026-11-19 재수집본 기준).

## 6. 시연 대본 (약 5분)

1. **시작(30초)**: 앱을 열고 "데모 계정으로 시작". 민지(26세, 서울 강북구, 미취업)의 홈. 맞는 정책 건수와 마감이 가까운 정책이 보인다.
2. **챗봇(1분)**: "자격증 응시료" 칩. AI가 검색어를 고르고 결과 건수를 알려 준다. 받고 있는 지원을 되묻는다 → "국민취업지원제도" 선택 → 다시 찾는다.
3. **결과와 근거(1분)**: "청년 국가기술자격 응시료 지원" 열기. 나이 줄의 근거 시트에 공식 페이지 문장이 나온다. "공식 페이지에서 보완한 정보"에 출처가 붙어 있다.
4. **서로 막는 정책(1분)**: 응시료 정책 두 개를 골라 신청 계획 만들기. "국민취업지원제도 및 타지자체 동일·유사사업 참여자" 문장이 경고로 나온다. 통합 서류와 순서.
5. **저장(30초)**: 신청 전 점검 → 승인 → 내 신청에 확인할 일이 저장되고 새로고침해도 남는다.
6. **검수(1분)**: `/review`에서 초안을 열어 출처 문장을 확인하고 승인하는 과정을 보여 준다. 승인하면 앱에서 "검수 완료"로 바뀐다.
7. **AI가 꺼졌을 때(30초, 선택)**: 모델을 끄고 같은 질문 → "AI 없이 낱말로 찾았어요"로 동작.

## 7. 한계 (질문이 나오면 그대로 답할 것)

- 결과는 수집값(API) 기준이다. 수집값은 공고와 다를 수 있어(팀 대조 45건 중 32건) 자격을 확정하지 않고 공식 페이지에서 확인하도록 넘긴다.
- 시군구 이름 261개는 행정표준코드관리시스템에서 확인했지만 사람 검수 전이다. 2026-07-01 폐지된 인천 중구·동구·서구가 어느 새 구로 이어지는지는 반영하지 못했다.
- 소득은 기준 중위소득·도시근로자 월평균소득 대비 비율, 연소득 상한, 학자금 지원구간만 비교한다(소득 조건이 있는 569건 중 263건). 건강보험료 기준, 부모·부부 합산, 재산 기준은 비교하지 않고 '확인 필요'로 남긴다.
- 지원 금액 합산, 다음 모집일 예측은 하지 않는다.
- 로그인과 공개 배포는 없다. 로컬 AI를 쓰는 구조라 서버 PC가 켜져 있어야 한다.
- 실제 사용자 대상 효과 측정은 하지 않았다.
