# 청년비서 서비스 사용 안내 (v0.13)

서비스: http://127.0.0.1:8000/ 또는 /desk/ (앱 화면) · 이전 화면은 /classic · 가상 정책 시연은 /lab

## 앱 화면 이용 흐름 (v0.13 · 2026-11-18)

팀 프로토타입을 기준으로 만든 화면이다. 폰 폭에 맞춰져 있고 넓은 화면에서는 가운데에 폰 크기로 보인다.

1. **시작**: "데모 계정으로 시작"(가상 인물 민지: 26세·서울·미취업자) 또는 "내 정보 입력하고 시작"(나이·거주 시도·취업 상태·최종 학력). 내 정보는 이 브라우저에만 저장한다.
2. **홈**: 내 정보로 본 정책 건수(조건 맞아요 / 확인 필요 / 조건 달라요), 진행 중인 신청, 주제 칩. 건수는 API에 적힌 값과 비교한 것이며 자격 판정이 아니다.
3. **챗봇 상담**: 주제 칩을 누르거나 "자격증 시험 쳤는데 지원받을 수 있어?"처럼 묻는다. 로컬 AI가 검색어를 고르고, 건수와 안내 문장은 코드가 만든다. 내 정보에 빠진 것은 지역 → 나이 → 취업 상태 순서로 하나씩 되묻는다. AI가 꺼져 있으면 안내 문구가 나오고 홈의 "맞는 정책부터 보기"로 계속 찾을 수 있다.
4. **결과**: 상태 칩으로 좁히고, 카드를 눌러 상세를 보거나 체크박스로 최대 5개를 고른다. 같은 정책이 여러 번 등록돼 있으면 하나로 묶어 "같은 정책 n건 등록"을 표시한다.
5. **정책 상세**: 조건 대조(API 조건과 내 정보), 조건을 누르면 근거 시트, 공식 페이지에서 보완한 정보(사람 검수 전, 원문 문장·출처 포함), "AI에게 물어보기".
6. **신청 계획 → 신청 전 점검**: 통합 서류(공통/일부 표시, 보유 체크), API 마감일 순서, 중복 수혜 확인 필요, 문의 문구 복사. "승인하고 내 신청에 저장"을 눌러야 저장된다.
7. **내 신청**: 저장한 확인 작업을 완료 표시한다. 새로고침해도 남는다.

시연 예시: 데모 계정 → "자격증 응시료" 칩 → 결과 보기 → 정책 2개 선택 → 신청 계획 만들기 → 신청 전 점검 → 승인 → 내 신청.

자동 확인: 서버를 띄운 뒤 `tests/browser_mobile_smoke.py`(주소는 환경 변수 `APP_URL`, 기본 8000번).

아래는 이전 화면(/classic)의 안내다.

## 실제 이용 흐름 (/classic)

1. **정책 찾기**에서 지역·정책명·기관을 검색하거나 분야를 고른다. 기존 온통청년 수집 데이터 4,020건을 조회하며 검색마다 외부 API를 호출하지 않는다.
2. 카드의 별 버튼을 누르면 **관심 정책**에 저장된다. 저장된 정책은 브라우저를 다시 열어도 같은 준비 공간에서 확인할 수 있다.
3. **자세히 보기**에서 지원 내용, 신청기간 원문, 조건, 서류와 출처를 확인한다. 원문 대조 기록이 있으면 API 기간과의 차이, 마감 안내 및 확인일을 표시한다.
4. **준비할 일 확인하기**에서 제안된 일을 읽고 **승인하고 준비판에 저장**한다. 일반 수집 정책에는 접수기간·자격/중복 제한·서류의 공식 확인 작업을 제안한다. 종료 대조 기록이 있는 회차는 다음 모집공고 확인을 제안한다.
5. **나의 준비판**에서 직접 확인한 일을 완료 표시한다. 자료가 변경되면 오래된 작업을 완료 처리할 수 없으며, 정책 상세에서 새 목록을 확인하고 다시 승인한다. 재승인은 해당 정책의 작업 목록을 교체하며, 변하지 않은 작업의 완료 상태는 유지한다.
6. **AI에게 물어보기**는 선택 정책과 준비 작업을 실제 로컬 Ollama 도구로 조회한 뒤 질문에 맞는 확인 항목을 고른다. 안내 문장은 검증된 고정 문구로 구성하며 모델의 자유 서술은 표시하지 않는다. 자동 저장·신청은 하지 않는다. 접수기간과 원문 대조일은 서버의 기록을 별도로 보여준다.

## 시연 예시

- 아무 정책 검색 → 별 저장 → 관심 정책에서 상세 열기 → 준비할 일 승인 → 완료 → 새로고침 후 복원.
- 정책번호 `20261021005400214208` 검색 → API와 공식 접수기간 차이 확인 → 과거 회차 종료와 새 모집 확인을 구분.
- 같은 상세에서 “공식 안내의 모집기간과 다음에 확인할 일을 도구로 확인해줘” 질문 → 실제 두 도구 실행 표시 → AI가 작업을 저장하지 않았음을 확인.
- 기존 규칙 엔진·가상 프로필·실제 수급 이력 분기 시연은 http://127.0.0.1:8000/lab 에 보존했다.

## 실행과 데이터

- Windows: `run_windows.bat`, AI: `run_ollama.ps1`.
- 기존 FastAPI/SQLite/Ollama를 사용하며 새 유료 서비스나 계정은 필요하지 않다.
- 준비 공간 식별자는 이 브라우저의 localStorage에, 관심 정책·작업·상태는 SQLite에 저장된다. 브라우저 저장소를 지우거나 다른 브라우저를 쓰면 동일 공간이 자동 복원되지 않는다. 계정 로그인·기기 간 동기화 서비스는 아니다.
- 관심 정책 해제는 이미 저장한 준비 작업을 삭제하지 않는다.
- 관심 정책과 준비 대상은 각각 최대 100개. 실제 증명서 업로드는 제공하지 않는다.

## 현재 범위

로컬에서 작동하는 서비스 MVP다. 공개 배포·계정 인증·심사위원 원격 접근은 아직 준비하지 않았다. 인증 없는 기존 검수 API도 있으므로 이 실행 서버를 그대로 인터넷에 노출하지 않는다.

실제 정책 데이터의 모든 자격 조건은 검수되지 않았다. 따라서 준비판에 저장되는 것은 **공식 조건을 확인할 작업**이며, 개인별 적격 확정이나 완성된 제출서류 판정이 아니다. 수집 날짜 이후 공고가 바뀔 수 있고 AI 설명에도 오류가 있을 수 있다. 개인정보 없이 가상 상황으로 체험한다.

## 개발 연결

- 화면: `static/desk.html`, `desk.css`, `desk.js`.
- 준비 공간·관심·승인·완료 API: `desk_service.py`, `/api/desk/workspaces/...`.
- AI: `desk_agent.py`, 읽기 전용 `read_policy` / `preview_tasks` 두 도구. 도구를 모두 실행하지 못한 답변은 성공으로 반환하지 않는다. 모델은 접수기간/자격/중복/서류/새 공고 중 확인할 항목을 선택하고, 서버가 허용한 문구만 보여준다. 최초 실연결 검증에서 자유 답변의 날짜 혼동과 과도한 현재시점 단정이 관찰되어 이 구조로 바꿨다. 고정 문구를 모델이 새로 작성한 설명으로 주장하지 않는다.
- 정책 API 키를 브라우저나 모델에 보내지 않는다. AI 이력에는 실행 상태·도구 이름·시간만 기록하며 질문 원문은 DB에 저장하지 않는다.
- 새 DB 테이블: desk_workspaces, desk_bookmarks, desk_tasks, desk_agent_runs.
- 정책 해시와 원문 대조 기록을 묶어 미리보기 토큰을 만든다. 다른 준비 공간 토큰이나 오래된 토큰으로 승인할 수 없다. 사용자 승인과 DB 트랜잭션을 유지한다.
