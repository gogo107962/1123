# 구현·검증 결과

작업 기간: 2026-11-15~17 (한국 시간). 서비스 검증: 2026-11-17. 단계별 최종 코드와 검증 범위는 아래 v0.8 기록을 참고한다.

## 결과

기존 FastAPI + SQLite + Vanilla JS 프로젝트를 유지하여 **가상 정책 데이터 입력 → 자격·방향성 중복 제한 판별 → 조건별 서류 준비 → 로컬 LLM의 도구 선택·실행 → 사용자 승인 → DB 저장·복원** 흐름을 검증했다. 전체 실제 정책을 검수하거나 운영 서비스를 완성했다는 뜻은 아니다.

시간은 이 PC에서 세션 생성 등 준비 API 요청을 포함해 측정한 두 사례다. 평균 성능·모든 입력의 정확도·응답 시간 보장을 의미하지 않는다. 시험 환경은 Windows, Python 3.13.7, 메모리 약 32GB, RTX 3050 4GB Laptop GPU, Ollama 0.40.16, qwen3:4b였다.

최종 pytest에는 Starlette의 httpx TestClient 사용 중단 예정 경고 1건이 있다. 실패는 없으며 검증된 의존성 조합을 `requirements-lock.txt`에 기록했다. 현재 프로덕션 코드 변경 없이 해당 경고를 숨기지 않았다.

## 수정한 동작

- 정책 조건의 연산자와 값 타입을 함께 검증한다. 미표현 조건은 `manual_checks`로 남겨 확인 필요로 처리한다.
- 대체서류 조건이 미확인인 경우 기본 서류를 확정하지 않는다. 여러 대체 조건이 동시에 참이면 임의로 첫 항목을 고르지 않는다.
- 서류 보유는 자기 신고로 취급하며 원문 조건 확인 작업을 유지한다.
- `/api/preview`의 토큰으로 사용자가 본 조건을 고정한다. `/api/confirm`은 현재 조건·정책·날짜와 토큰이 다르면 409로 거부한다.
- 정보·선택·서류·정책 내용 변경 후 기존 작업은 재확인이 필요하다. 오래된 작업의 완료 처리도 거부한다. 재승인 시 유효 작업은 할 일로 갱신하고 불필요해진 작업은 과거 기록으로 보존한다.
- SQLite 기존 작업에 fingerprint 컬럼을 추가하는 마이그레이션을 검증했다. 작업 ID는 보존하고 최초 재승인을 요구한다.
- 모델이 반환한 도구 이름·인수는 서버가 검증한다. 사실 추출은 제안 단계이며 사용자가 확인해야 저장한다. 모델에 준비 작업 저장·신청 도구는 제공하지 않는다.
- 모델 미연결, 잘못된 인수, 허용되지 않은 도구, 출력 잘림, 시간초과, 호출 횟수 초과를 처리·기록한다.
- 마지막 가상 세션 ID를 브라우저에 보관해 새로고침 후 준비판을 복원한다.

## AI 실연동에서 발견한 실패와 최종 방식

첫 native tools 요청에서 설치된 모델은 도구를 실행하지 않고 설명만 생성했다. 이 결과는 성공으로 계산하지 않았다. 원인을 특정 라이브러리 버그로 확정하지 않는다.

최종 구현은 [Ollama JSON 스키마 출력](https://docs.ollama.com/capabilities/structured-outputs)을 사용한다. 모델이 `calls` 배열에 실행할 도구 이름과 인수를 생성하고, 서버가 허용 목록·타입을 검사해 실제 함수를 실행한 뒤 결과를 모델에 돌려준다. 규칙/키워드로 도구 실행을 흉내 내는 방식이 아니다. native function calling과는 구분해서 설명해야 한다.

실제 모델 검증에 사용한 도구는 `update_user_facts`, `analyze_selected_policies`, `preview_preparation_tasks`다. 자연어 답변에는 오류 가능성이 남으므로 화면의 규칙 판별 결과와 출처가 기준이다. `grounded=true`는 판별 또는 준비 도구를 실행했다는 표시이며 문장별 사실 검증 완료를 의미하지 않는다.

## 재현

프로젝트 폴더에서 실행한다.

```powershell
# 최초 설치 또는 검증 환경 재현
.\.venv\Scripts\python.exe -X utf8 -m pip install -r requirements-lock.txt

# 이미 받은 모델은 재사용된다. Ollama는 숨김 백그라운드로 실행된다.
.\run_ollama.ps1
.\.venv\Scripts\python.exe -X utf8 start.py
```

별도 터미널에서:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest -q
.\.venv\Scripts\python.exe -X utf8 tests/browser_smoke.py
.\.venv\Scripts\python.exe -X utf8 tests/live_agent_smoke.py
.\.venv\Scripts\python.exe -X utf8 tests/live_fact_smoke.py
.\.venv\Scripts\python.exe -X utf8 tests/browser_agent_smoke.py
```

브라우저 테스트는 설치된 Microsoft Edge를 사용한다. live/browser 스크립트는 실행 중인 로컬 서버에 가상 세션과 작업을 생성한다. `pytest`는 임시 DB와 모의 모델 전송을 사용하므로 실제 모델 성공 증거와 구별한다. Windows 샌드박스의 socketpair 제한 때문에 TestClient가 멈춘 사례가 있어, 본 검증은 허용된 일반 실행 환경에서 진행했다.

## 시연 순서

1. `http://127.0.0.1:8000`에서 **청년수당 수급 중** 선택: 가상 월세 정책의 방향성 제외와 근거를 확인한다.
2. **서울 취업준비생** 선택: 신청 검토 가능과 현금 월세 대체서류를 확인한다.
3. AI 입력: “가상 프로필에서 나이는 27세이고 월세는 계좌이체로 냈어. 이 두 정보만 변경 제안하고, 변경된 조건으로 자격 분석과 준비 서류를 도구로 확인해 줘. 아직 저장하지 마.”
4. 실제 도구 실행 표시를 확인하고 **위 정보 제안을 확인하고 저장·재분석**을 누른다. 월세 이체내역으로 준비판이 바뀌는지 확인한다.
5. **이 작업들을 승인하고 DB에 저장**을 누르고 작업 하나를 완료한다. 새로고침해 상태가 유지되는지 확인한다.
6. 월세 납부 방식을 바꾸면 기존 작업이 재확인 상태가 된다. 검수 대기 목록의 공식 정책은 선택할 수 없음을 설명한다.

## 취약점 검토와 보완 · 검수용 정책 초안 (v0.17 · 2026-11-18)

검토 범위는 11/17~18에 추가한 코드(걸러보기, 대화, 신청 계획, 앱 화면)와 그 주변이다. 외부 도구로 한 침투 시험이 아니라 코드 읽기와 측정이다.

- 찾은 것과 조치
  - 보안 헤더가 전혀 없었다 → 모든 응답에 `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, 그리고 `/docs`를 뺀 경로에 CSP(`script-src 'self'`, `frame-ancestors 'none'` 등)를 붙였다. 화면이 서버 데이터를 innerHTML로 그리므로, 이스케이프가 빠지는 실수가 있어도 인라인·외부 스크립트가 실행되지 않게 하는 2차 방어다. 이를 위해 `mobile.html`의 인라인 `onload`를 없앴다.
  - 걸러보기·대화·홈이 요청마다 4,020건을 다시 구조화했다(0.78초, 인증 없이 누구나 호출 가능) → 구조화 결과를 메모리에 두고 수집 내용이 바뀔 때만 다시 만든다(다음 호출 0.04초).
  - 로컬 모델 호출에 동시 제한이 없었다 → 한 번에 한 질문만 받고, 답하는 중이면 429로 거절한다.
  - AI가 꺼지거나 응답이 틀리면 대화가 멈췄다 → 정해 둔 낱말 20개로 찾는 대체 경로를 두고, 응답의 `ai` 값과 화면 문구("AI 없이 정해 둔 낱말로 찾았어요")로 AI가 한 일이 아님을 밝힌다. 유료·외부 AI로 바꾸지 않는다.
  - 화면에서 이스케이프하지 않던 값 3곳(서류 키·이름, 시군구 코드)을 이스케이프했다. 모두 서버 상수라 실제 위험은 낮았다.
- 확인만 하고 그대로 둔 것(공개 배포 전에 정해야 함)
  - 인증이 없다. 수집 실행(`POST /api/integrations/ontong/sync`), 기존 에이전트(`/api/agent/message`), 준비 공간 생성이 누구에게나 열려 있다. 준비 공간은 만들 때마다 DB에 행이 남고 개수 제한이 없다. 로컬 실행(127.0.0.1) 전제다.
  - 준비 공간 식별자는 브라우저 localStorage에 있고 그 값을 아는 사람은 그 공간을 쓸 수 있다. 계정이 아니다.
  - 요청 횟수 제한은 모델 호출의 동시 1건뿐이다.
  - 모델에 보내는 것은 사용자의 말뿐이고 정책 글은 보내지 않는다. 모델 출력은 형식 검증 뒤 검색어·나이·취업 상태로만 쓰고 화면 문장으로 쓰지 않는다. 사용자가 지시문을 넣어도 화면 문장은 바뀌지 않는다(모의 응답 테스트로 확인, 실제 모델에 공격 문장을 넣어 보지는 않았다).
- 검수용 정책 초안: `tools/draft_policy.py`가 수집 정책 하나를 `data/policies/`와 같은 형식의 초안으로 옮겨 `data/policy_drafts/`에 쓴다(서버가 읽지 않는 폴더). - **공식 페이지 확인 확대**: 지금 접수 중이고 날짜가 정해진 정책 가운데 아직 확인하지 못한 23건을 더 찾았다. 보완 기록 147개 항목(61개 정책) → **199개 항목(77개 정책)**, 나이 규칙 40개. 지금 접수 중·날짜 있는 비교 가능 정책 85건 중 63건(74.1%)에 공식 페이지 문장이 있다(사람 검수 전). 넣지 않은 것: 정책과 페이지의 연결이 추정인 것, 지역 포털의 등록 정보(API와 같은 성격), 신청 기간이 아닌 행사일·사업기간, 손으로 옮긴 표.
